# 设备账号访问规范

## 新增需求

### 需求：账号认证

服务 MUST 仅在有效账号会话下列出或连接已绑定设备。注册和登录 MUST 使用安全密码哈希、限速、同源校验与不泄露账号存在性的错误响应。

#### 场景：成功登录

- **当** 用户提交有效账号和密码
- **那么** 服务建立不可由脚本读取的 HTTPS 会话，并返回页面后续请求所需的 CSRF 令牌

#### 场景：错误或跨站登录

- **当** 密码错误、登录被限速或请求来源不是本站
- **那么** 服务拒绝请求，且错误响应不说明该账号是否存在

### 需求：设备所有权

首次有效配对 MUST 将设备登记到已认证账号。登记后稳定配对码 MUST 只作为显示标识；设备访问 MUST 同时验证所属账号会话。配对码不得单独重连或跨账号访问。

#### 场景：首次认领

- **当** 已登录用户在首次配对期限内提交有效配对码
- **那么** 服务将该采集端密钥绑定到该用户并返回稳定设备标识

#### 场景：账号选择设备

- **当** 用户登录后选择其名下设备
- **那么** 浏览器无需输入配对码即可连接该设备

#### 场景：越权访问或撤销

- **当** 另一账号选择设备、提交配对码重入已认领设备，或所有者已撤销设备
- **那么** 服务拒绝连接并且不影响设备所有者的其他会话

### 需求：断线恢复

账号/设备授权 MUST 独立于瞬时 WebSocket 生命周期。采集端和网页端在临时网络断开后 MUST 保留稳定身份并自动重试；服务进程重启后 MUST 可从持久化元数据恢复在线/离线设备身份。只有明确撤销或停止共享才删除设备授权。

#### 场景：采集端断网

- **当** 采集端 WebSocket 意外断开
- **那么** 设备显示离线/重连中，所属网页保持授权并等待；采集端用原密钥返回后无需新配对码即可恢复取图

#### 场景：浏览器刷新或更换浏览器

- **当** 同一账号会话在浏览器刷新后恢复，或该账号在另一浏览器登录并选择设备
- **那么** 浏览器自动认证并连接原设备，无需输入配对码

#### 场景：主动撤销

- **当** 所有者撤销设备或采集端明确停止共享
- **那么** 服务关闭当前端点、删除该设备密钥授权，旧客户端凭据不能恢复

#### 场景：桌面端安全停止

- **当** 用户在桌面端停止共享
- **那么** 客户端必须先原子持久化本机停用标记，然后再等待服务器撤销；即使服务器暂时不可达，应用重启也不能恢复本机凭据

#### 场景：本机和服务器均无法确认停用

- **当** 本机停用标记写入失败且服务器撤销未确认
- **那么** 当前进程不自动重连，退出操作显示旧凭据可能恢复的明确警告，并允许用户重试停止

### 需求：最少持久化

持久化存储 MUST 仅包含账号验证资料、会话/CSRF 哈希和设备归属/认证哈希。截图、模型 API Key、配置、提示词与对话 MUST 只在在线连接中转发，不得写入状态存储或日志。

#### 场景：服务重启

- **当** 中继进程重新启动
- **那么** 账号和设备授权可恢复，在线端重新认证；重启前的帧请求和截图不恢复也不落盘
