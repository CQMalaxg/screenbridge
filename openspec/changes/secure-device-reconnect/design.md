# 安全设计

## 信任边界

- 账号会话只授权账号所有者查看和撤销其设备。会话令牌由浏览器通过 `Secure`、`HttpOnly`、`SameSite=Strict` Cookie 携带；CSRF 写操作同时要求同源 `Origin`、Cookie 与请求头中的 CSRF 令牌一致。
- 采集端有独立的 256 位随机设备密钥。中继只保存其哈希；设备码是稳定标识，不是访问凭据。首次绑定后只有所有者账号能连接，单独提交设备码不能恢复访问。
- 反向代理只能在可信来源地址提供的 `X-Forwarded-Proto: https` 下证明 TLS。默认只信任本机回环地址；服务也默认绑定 `127.0.0.1`，公网入口由 HTTPS 代理提供。
- 桌面端只在系统加密可用时使用 Electron `safeStorage` 保存设备密钥。中继持久化目录在 POSIX 系统收紧为 `0700`，状态文件为 `0600`；写入使用同目录临时文件、同步落盘和原子替换。

## 恢复与撤销

- 瞬时网络断开只关闭 WebSocket，不删除账号设备登记。中继重启后从认证元数据恢复离线设备；桌面端和网页分别以指数退避和随机抖动重连。
- 网页刷新后由仍有效的账号 Cookie 恢复会话，并从账号设备列表连接所选设备。换浏览器时需登录同一账号，不需重新输入配对码。
- 账号登出、会话过期或设备撤销会关闭已授权查看连接。所有者撤销设备或桌面端明确停止共享会删除服务端设备记录。桌面停止共享时，必须先原子写入本机停用标记，再等待网络撤销；网络不可用时，桌面端仍无法从本机恢复旧设备密钥，用户可从网页撤销残留登记。
- 若本机停用标记写入失败，桌面端仍尽力请求服务器撤销。只有本机停用标记已写入或服务器确认撤销后，退出才可直接继续；两者均未确认时，应用阻止普通退出并给出明确风险选项，不能谎报停止成功。
- 图片、模型配置、API Key、提示词和对话只通过在线连接传输，不进入持久化状态或服务日志。

## 取舍与限制

- 会话最长 30 天，降低长期 Cookie 被盗后的持续访问风险。到期需要重新登录，但仍能从账号设备列表恢复，无需重新配对。
- 不支持密码找回；注册/登录限速，密码使用 scrypt 并带随机盐。
- 设备断电、休眠或离线期间不能采集屏幕；恢复联网后自动重连。
- 如果本机存储写入失败且中继同时不可达，无法确认设备授权已停用；应用必须保持当前进程阻止自动重连，并警告退出后本地旧凭据可能恢复。
- 首次绑定改为账号授权，旧的只靠配对码查看方式不再适用于已登记设备。

## 授权与回滚

- approval: 用户于 2026-10-17 授权实现安全断线恢复并要求先不更新线上；随后用户明确要求更新线上网页并更新本机安装包。
- 发布范围：本机 Windows x64 安装程序与 ZIP 位于 `dist/release-0.4.4/`；部署中继、四个网页资源和 systemd 状态目录配置。不得推送 Git、上传安装包、修改 Nginx/Docker 或其它站点。
- 影响：中继重启会断开当前 WebSocket；旧版桌面配对不会迁移为账号设备。更新后用户需安装新版，注册/登录账号并首次绑定；绑定后才有稳定的断线恢复。
- 回滚步骤：部署前将旧版 `relay.js`、`public/index.html`、`public/viewer.css`、`public/viewer.js`、`public/workbench.js` 和 systemd unit 备份并校验。发布失败时停止服务，逐项恢复上述六个文件与 unit；旧版服务器原本没有 `security-store.js`，因此移除本次新增文件。运行 `systemd-analyze verify`、daemon-reload 并启动旧服务。保留 `/var/lib/screenbridge` 新建目录及认证状态数据，不删除或覆盖；备份继续保留供进一步恢复。
- 状态目录：systemd 以 `screenbridge` 用户运行，`SCREENBRIDGE_STATE_DIR=/var/lib/screenbridge`，目录属主 `screenbridge:screenbridge`、POSIX 权限 `0700`，unit 仅对该目录开放写权限。
- 部署验证：先在本机构建并运行全量测试；线上切换后检查 unit 语法/状态、HTTPS 健康端点、关键网页资源和状态目录权限。不得打印状态文件、账号密码、Cookie 或密钥。
