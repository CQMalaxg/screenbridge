# 公网配对采集电脑与浏览器

## 问题

现有共享通过局域网 HTTP 端口提供画面，远程浏览器无法越过 NAT/防火墙直连采集电脑，也没有多用户隔离。

## 目标

采集端主动连接公网中继并生成短期配对码；持有配对码的浏览器可以经 HTTPS 请求实时截图。每个会话独立、限时，画面只在内存转发，不写入服务器。

## 非目标

- 不提供账户注册、长期设备目录、录制、回放或云端截图存储。
- 不改变现有模型、截图批次、提示词预设或局域网共享行为。
- 不让浏览器访问采集电脑的公网/局域网端口。

## 验收

- 多台采集电脑可各自创建不同配对码；错误码、过期码及非配对会话不能取图。
- 浏览器经 TLS 连接；采集端只向外连接中继；截图按请求传输且不落盘。
- 服务端限制配对码尝试频率和单房间连接数，房间到期后释放资源。
- 现有 Nginx 网站和容器保持可用，新增入口可以单独回滚。
- `npm run check`、中继单元/集成检查及部署后 HTTPS/配对往返检查通过。

## 后续迭代：完整浏览器工作台

当前线上页面只有配对与查看一张画面，缺少桌面端的截图批次、模型设置、提示词预设和分析追问流程。本迭代将这些核心操作加入响应式网页，并保留采集端主动连接、按需取图和截图不落盘的边界。

- 行为目标：查看设备可以在网页完成配对、多张截图管理、模型/提示词设置、截图分析、连续追问和重试。
- 非目标：网页直接采集平板或浏览器设备的操作系统屏幕；账户系统或云端保存模型密钥、截图、对话与预设。
- 本机数据：设置与提示词预设保存到当前浏览器；API Key 默认只在当前页面内存中，用户勾选后才保存在该浏览器。
- 模型调用：由浏览器直接请求用户配置的模型服务；模型服务需允许来自工作台域名的跨域请求，失败时给出具体排查提示。中继不接触模型密钥和分析请求。
- 移植方式：直接复用桌面端 `renderer/index.html`、`renderer/styles.css` 与渲染层的截图、模型配置、预设和会话代码；只为浏览器替换 Electron 专属采集/IPC接口并增加公网配对入口。
- 验收：所有核心桌面工作流可在桌面和移动浏览器完成；截图可多张添加/选择/删除；预设数量不限；流式分析/追问可停止、清空、复制和重试；本机检查与公网工作台验证通过。
- 回滚：保留桌面端和已部署配对协议；恢复旧网页静态资源并重载专属中继服务即可。

## 后续迭代：配对成功后保持长连接

- 目标：配对码只限制首次连接时限；浏览器成功加入后，只要浏览器与采集端仍连接，房间就不会因 15 分钟计时而结束。
- 行为：未使用的配对码仍在创建 15 分钟后失效。首次查看端成功连接即进入活动会话；关闭/断开任一端或采集端点击停止共享时，立即撤销房间与配对码。
- 非目标：永久设备配对、断开后自动保留房间、账户系统、截图或模型数据持久化。
- 验收：活动会话跨过原配对码有效期仍可正常取图；未连接的过期码仍被拒绝；活动房间中第二个查看端仍被拒绝；任一端断开后另一端收到断开提示，旧码不能再连接。
- 回滚：恢复 `/opt/screenbridge/server/backups/browser-workbench-20261010-1/predeploy.tar.gz` 中的服务器文件并重启专属中继；Windows 用户可重装之前生成的 `屏桥 ScreenBridge Setup 0.4.0.exe`。
- approval: 用户于 2026-10-10 明确要求“只要连接就不会断开，除非浏览器或者本地断开”；沿用此前用户对该服务器部署屏桥的授权。

## 后续迭代：网页回答选区放大与截图自动清理（iteration 6）

- 问题：网页回答中的小段文字不便阅读；截图分析后仍留在待分析栏，需手动清除；Responses API 追问把历史助手回答错误地编码为 `input_text`，导致 HTTP 400。
- 目标：选择回答文字时就近显示放大预览；点击分析后立即清空可见的待分析截图，同时保留本轮截图供重试和可选附图；Responses API 追问使用角色对应的文本类型编码历史消息。
- 非目标：调整模型供应商、重试任意无效请求、保存截图到本地/服务器或改变桌面端行为。
- 允许范围：`server/public/index.html`、`server/public/viewer.css`、`server/public/workbench.js`、`server/public/viewer.js`、`server/test/viewer.test.js`、本迭代关联规格/任务/验证/checkpoint；线上只更新 `/opt/screenbridge/server/public/` 中对应静态文件。
- 验收：只在回答文字选区非空时显示放大浮层，并在清除选区、选择区离开回答或视窗变化时隐藏；分析开始后待分析栏为空，失败/停止后仍可重试，追问可按勾选附带最近分析截图；Responses API 中用户文本使用 `input_text`、助手文本使用 `output_text`，HTTP 400 仍展示服务端原始错误详情。
- 验证：`npm.cmd run check`、`npm.cmd test`、`git diff --check`；线上更新前备份静态文件，更新后检查 HTTPS 页面资源和 `/healthz`，保留可恢复备份；人工视觉验收为 optional。
- approval: 用户此前明确要求将网页版功能更新到线上；本次部署只覆盖本迭代对应的静态文件。

## 后续迭代：网页配对会话恢复（iteration 7）

- 问题：查看网页刷新或短暂断线会让中继立即销毁已配对房间，即使采集电脑仍在线，用户也只能在电脑端重新创建配对码。
- 目标：首次配对后为当前浏览器签发独立高熵恢复凭据；网页刷新、重新打开或短暂断网时自动重连；采集电脑保持既有长连接和运行状态。
- 非目标：修改桌面端配对流程、允许配对码重复加入、跨浏览器/设备自动同步恢复凭据、在中继持久化会话、在中继重启或采集端停止后恢复旧房间。
- 允许范围：`server/relay.js`、`server/public/index.html`、`server/public/viewer.js`、`server/test/relay.test.js`、`server/test/viewer.test.js`、本迭代关联规格/任务/验证/checkpoint。
- 安全边界：中继只保存恢复凭据哈希；恢复令牌存储于当前浏览器本地，只有持令牌者可以续接；短配对码建立会话后不可复用；手动断开清除浏览器令牌并结束配对；采集端停止/断开或中继重启后令牌失效。
- 验收：网页重载、网络恢复、旧网页连接迟到关闭时仍能恢复唯一查看连接；错误令牌被拒且不能中断现有查看者；短配对码不能重复进入；采集端停止后房间和令牌失效；全量测试与语法检查通过。
- 部署授权：用户于 2026-10-12 明确要求“部署到线上”，仅授权更新 `/opt/screenbridge/server/relay.js`、`/opt/screenbridge/server/public/index.html`、`/opt/screenbridge/server/public/viewer.js`，并重启专属 `screenbridge-relay.service`。
- 回滚：从本次专属备份恢复上述三个文件并重启 `screenbridge-relay.service`；确认本机 `/healthz`、公网 `/healthz` 与文件哈希恢复。不得改动 Nginx、Docker、其它站点或 systemd unit。
- 部署影响：重启会清除中继内存中的活动配对会话；部署时在线的用户需重新配对一次，之后网页刷新可自动恢复。

## 后续迭代：对话时手动选择模型（iteration 8）

- 问题：依赖请求超时或失败再按优先级顺延，会让用户在主模型卡住时等待过久；对话界面无法直接选择其他已配置模型。
- 目标：桌面端和网页端分别为截图分析与追问提供模型选择；每次请求只使用当前选择，切换追问模型继续使用已有对话上下文；采集端同步模型列表后网页仍可自行选择。
- 范围：`main.js`、`renderer/index.html`、`renderer/renderer.js`、`renderer/styles.css`、`server/public/` 中四个工作台文件、相关测试及本迭代文档。按 Lite 处理单一模型选择闭环；兼容已有配置结构，密钥保存、传输和配对边界不变。
- 非目标：取消此前已撤销的“无需截图即可聊天”限制、修改配对协议、并发请求所有模型、自动中途换模型或提交推送。此次先完成本机实现与验收，尚无本轮上线/重新打包操作。
- 验收：两个入口实际发送所选预设 ID；旧配置的优先级/自动切换值不再触发其他模型；同步更新不覆盖仍存在的手动选择；生成期间选择锁定，停止后可改选再请求；配置中的模型被删除时选择回到可见的默认项；设置中不再显示优先级/自动顺延；保留现有预设、地址、密钥和上下文。
- 基线：沿用 iteration 7 的 23/23 测试与语法通过证据；本轮首次局部检查为工作区修改后的 9/9 viewer 测试通过，新增用例覆盖显式选模及失败不顺延，未伪记修改前 RED。
