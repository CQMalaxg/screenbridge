# 屏桥 ScreenBridge

屏桥是一个 Windows 和 macOS 屏幕助手：采集电脑可以通过公网配对或局域网共享，将画面发送给电脑/平板上的查看设备，再截取远程画面交给视觉模型分析，并围绕模型的回答继续追问。

适合用于模拟面试、培训、演示和经过允许的无障碍辅助场景。

## 下载

从 GitHub Releases 下载最新版本：

<https://github.com/CQMalaxg/screenbridge/releases>

- `ScreenBridge.Setup.0.4.4.exe`：Windows 安装包，推荐普通用户使用
- `ScreenBridge-0.4.4-win.zip`：免安装便携版

安装包安装完成后，直接从开始菜单或桌面启动“屏桥 ScreenBridge”。使用安装包不需要另外安装 Node.js 或 npm。

### macOS

macOS 通用版由仓库的 GitHub Actions 手动构建：打开 **Actions → macOS build → Run workflow**，构建完成后下载 `screenbridge-macos-*` artifact，其中包含 DMG 和 ZIP。通用包支持 Intel 与 Apple 芯片。

当前构建未使用 Apple Developer ID 签名或公证。首次打开时，macOS 可能提示无法验证开发者；在 Finder 中按住 Control 点击应用并选择“打开”，然后确认系统提示。首次启动或截图时如果屏幕监听失败，按应用提示前往“系统设置 → 隐私与安全性 → 屏幕录制”允许屏桥访问屏幕，再完全退出并重新打开应用。

## 功能

- 单机屏幕截图与视觉模型分析
- 针对视觉模型回答的多轮对话追问
- 视觉模型与对话模型分别独立配置，各自支持多个预设
- 截图回答提示词与追问提示词可分别保存任意数量的预设
- 顶部导航栏“设置”统一管理模型、预设与系统提示词
- 两台电脑局域网屏幕共享
- 通过公网服务器和短时配对码连接不同网络中的电脑/平板浏览器
- 多位用户可各自创建独立配对会话；每台采集电脑运行自己的屏桥应用
- 自动发现局域网内正在共享屏幕的设备
- 配对码保护的远程画面访问
- 连续添加多张截图并一次分析
- 保存多个模型预设并快速切换
- 模型请求失败后按优先级自动切换
- 使用当前截图批次切换模型重试
- 流式回答和 Markdown 渲染
- 支持 Responses API 和 Chat Completions
- 支持 Right.ai 等 OpenAI 兼容接口

## 最快开始：单机模式

适合先验证模型配置和截图分析功能。

1. 启动 App。
2. 点击右上角“设置”，在“视觉模型”页填写模型服务信息。
3. 需要追问时，再切到“对话模型”页填写对话模型信息。
4. 点击“保存设置”。
5. 默认使用“单张快捷”模式，点击“清空并截图分析”即可截取当前屏幕并立即提交；回答完成后再次点击即可开始下一题。
6. 需要分析多张时切换到“多图批次”，连续点击“添加截图”，检查缩略图后点击“分析 N 张截图”。缩略图可切换预览或单独删除。

截图时 App 窗口保持显示，并会从采集画面中排除助手窗口，避免画面闪烁。

## 多轮对话追问

截图分析完成后，右侧回答区会保留这一轮对话上下文。

1. 在回答区下方输入框填写追问内容。
2. 按 `Ctrl + Enter`，或点击“发送追问”。
3. 勾选“附带当前截图”可以连同当前截图批次一起发送；默认只发送文本上下文，速度更快。
4. 点击“清空对话”结束当前这一轮上下文。

追问由“对话模型”处理，第一次截图分析由“视觉模型”处理，两者互不影响。追问时会把之前的提问与回答一起作为上下文发送给对话模型。

## 提示词预设

“告诉模型怎么答”和追问输入框各有独立的提示词预设列表。点击“新增”后填写名称和提示词内容即可保存；对话框会带入当前输入内容，选择预设会将内容载入对应输入框。修改内容后点击“更新”覆盖当前预设，也可以删除不再需要的预设。两个列表保存在本机配置中，预设数量不设上限。

## 跨网络配对模式

采集电脑需要启动屏桥；查看设备只需要打开浏览器，可以使用平板。两端都通过 HTTPS/WSS 连接公网中继，所以不要求在同一局域网，也不需要在家用路由器上设置端口转发。

### 采集电脑

1. 启动屏桥，展开“公网配对”并点击“创建配对码”。首次绑定码只在 15 分钟内有效。
2. 把查看页面和配对码交给查看设备；网页登录或创建账号后完成首次绑定。
3. 绑定后设备码保持不变。网络或中继短暂中断、屏桥重启后会自动恢复。
4. 需要解绑时点击“停止共享”。程序先在本机安全存储写入停用标记，阻止重启恢复，再尝试撤销服务器设备登记；如果中继暂时不可达，可登录网页从设备列表撤销。

设备密钥只由桌面端通过 Electron `safeStorage` 加密后保存在当前系统用户目录。正常关闭窗口会隐藏到托盘或菜单栏；从菜单退出不会撤销设备，重新启动屏桥后会自动恢复。勾选“登录系统后自动启动并恢复公网连接”后，下次登录时屏桥会在后台启动并恢复连接。

如果本机停用标记写入失败且服务器也无法确认撤销，屏桥会在退出前提示设备凭据可能恢复；建议继续运行并重试停止共享。

### 查看设备

1. 在电脑或平板浏览器打开采集电脑显示的查看页面。
2. 登录与采集电脑绑定的账号；首次使用时创建账号并输入配对码绑定设备。
3. 后续刷新网页、换浏览器或网络中断后会从账号设备列表自动连接，无需再次输入配对码。不同浏览器需要登录同一个账号。
4. 点击“添加截图”连续截取多张画面，再点击“分析 N 张截图”。截图缩略图可切换预览或单独删除。
5. 点击“设置”分别配置视觉模型和对话模型；可保存多个模型预设，并配置失败回退。回答提示词、追问提示词也各自支持不限数量的预设。
6. 截图分析完成后，可以继续多轮追问、复制回答、停止生成或使用当前截图批次重试。

#### 连接后的完整配置同步

查看设备连接采集电脑后，网页会自动以采集电脑的配置为准，并在公网连接收到更新或局域网轮询发现变化时同步以下全部内容：

- 视觉模型和对话模型的 API 地址、API 协议、API Key、HTTP 代理、模型名称
- 两组模型预设的名称、列表、主用预设、请求优先级、启用状态和自动切换开关
- 视觉与对话系统提示词
- “告诉模型怎么答”和追问提示词预设的列表、名称及文字内容

连接期间网页设置为只读，选择提示词预设仍会把同步后的文字载入对应输入框。断开采集电脑后，网页会恢复到该浏览器原来保存的设置。公网配置通过已经建立的 WSS 配对连接实时转发；局域网配置通过带配对码的 `/config` 接口持续读取。API Key 只在这条已建立的连接中传输，不写入中继服务器磁盘；模型请求仍由浏览器直接发送至模型服务。浏览器不能强制使用桌面 App 的独立 HTTP 代理，网页请求遵循查看设备的浏览器/系统代理。

未连接采集电脑时，网页上的设置保存在当前浏览器。API Key 默认只在当前页面有效；需要跨刷新保留时，在设置中勾选“在此浏览器记住”。截图和对话只保存在当前页面内存，服务商需允许工作台网页跨域访问。

配对码需在创建后 15 分钟内完成首次绑定。绑定后设备归账号所有，配对码只作为稳定设备标识，不再单独授权访问。网页账号会话使用 `Secure; HttpOnly; SameSite=Strict` Cookie，最长 30 天；到期后重新登录即可从账号设备列表恢复，不需要重新配对。账号密码目前没有邮箱找回功能，请妥善保管。

中继重启时账号和设备登记会从状态目录恢复，采集端与网页重新认证后继续连接。断网或采集电脑关机期间不能截取屏幕；采集电脑恢复上线后网页会继续等待并自动恢复。每个绑定设备同时允许一个查看网页连接。不同用户各自登录自己的账号并绑定自己的采集电脑，设备和截图彼此隔离。

默认公网入口为 `https://screenbridge.zahml.top`。如使用自建服务器，可通过 `SCREENBRIDGE_RELAY_URL` 环境变量指定 HTTPS 中继地址。服务器使用 Let's Encrypt HTTP-01 证书，并通过独立 systemd 定时器自动续期；公网服务必须使用有效 TLS 证书。

启用账号/设备恢复后，中继必须把 `SCREENBRIDGE_STATE_DIR` 指向专用、可持久化的状态目录，例如 `/var/lib/screenbridge`，并将目录所有者设置为运行中继的专用服务账号。POSIX 系统上目录使用 `0700`、状态文件使用 `0600`；备份也必须限制为服务管理员可读。状态文件只保存账号密码盐值哈希、会话/CSRF 哈希和设备归属/密钥哈希，不保存截图、模型配置、API Key 或对话。不要将该目录放在临时目录、应用发布目录或公开 Web 根目录。

公网反向代理必须与中继保持同机回环连接；默认只信任来自 `127.0.0.1` 或 `::1` 的 `X-Forwarded-Proto: https`。如果自建代理运行在其他地址，应在 `createRelayServer` 中仅加入该代理实际连接时使用的地址，不能信任任意公网来源提供的转发头。

## 双电脑局域网模式

两台电脑都需要安装并运行同一个 App。两台电脑必须连接到同一个局域网。助手端可搜索正在共享的设备；局域网搜索会发现地址，但不会广播配对码。

### 电脑 A：题目所在电脑

1. 启动“屏桥 ScreenBridge”。
2. 在“远程屏幕”区域点击“启动共享端”。
3. 记录显示的共享地址，例如：

   ```text
   http://192.168.1.20:8765
   ```

4. 记录显示的配对码。
5. 点击“最小化共享端”。

最小化共享端很重要，否则共享画面可能包含共享端自己的 App 窗口。

### 电脑 B：助手电脑

1. 启动“屏桥 ScreenBridge”。
2. 在“远程屏幕”区域点击“搜索设备”并选择电脑 A，地址会自动填入；也可以手动填写共享地址。
3. 填写配对码。
4. 点击“连接远程屏幕”。
5. 看到电脑 A 的画面后，在电脑 B 上点击“添加截图”；可连续添加多张，再点击“分析 N 张截图”。

电脑 B 会抓取远程画面的最新帧，并将图片发送给配置的视觉模型。

## 配置模型预设

点击顶部导航栏的“设置”打开模型设置。设置分为两个页签：

| 页签 | 用途 |
| --- | --- |
| 视觉模型 | 读取截图并给出第一版回答，模型必须支持图片输入 |
| 对话模型 | 针对已给出的回答继续多轮追问，一般不需要支持图片输入 |

两个页签各自维护独立的预设列表和独立的主用预设，互不干扰。导航栏右侧会显示当前生效的视觉模型和对话模型。

在每个页签中可以新增并保存多个模型。新安装不会预填 API 地址或模型名称，需要填写服务商提供的信息。每个预设独立保存以下配置：

| 配置项 | 示例 |
| --- | --- |
| API 地址 | 服务商提供的兼容 API 根地址，例如 `https://api.example.com/v1` |
| API 协议 | `Responses API` 或 `Chat Completions` |
| 模型名称 | 服务商提供的视觉模型名称 |
| API Key | 服务商提供的密钥 |
| HTTP 代理 | `http://127.0.0.1:7897`，没有代理可留空 |
| 请求优先级 | 正整数；数字越小，故障切换时越先尝试 |

在设置中选择一个预设并勾选“设为主用模型”，它会作为该页签请求的首选模型。启用“请求失败时按优先级自动尝试同组其他已启用预设”后，如果主用模型连接失败、返回错误或没有返回内容，程序会依次尝试其他参与自动切换的预设。请求错误会显示连接地址、服务端状态和可排查的配置项。

每个页签底部还有对应的系统提示词：视觉模型页是截图分析提示词，对话模型页是追问回答提示词，可按需修改。

需要手动换模型时，在设置里把另一个预设设为主用模型，然后点击“重试分析”，会复用当前截图批次，不需要重新截屏。旧版本保存的单模型配置会保留原有服务地址，并迁移为视觉模型和对话模型两组预设。

程序会根据协议请求：

```text
{API 地址}/responses
{API 地址}/chat/completions
```

视觉模型必须支持图片输入；对话模型在勾选“附带当前截图”时也需要支持图片输入。不要把真实 API Key 写入源码、README 或提交到 Git。

## 网络与防火墙

共享画面使用 TCP `8765` 端口，局域网发现使用 UDP `8766` 端口。第一次启动时，Windows 防火墙可能会弹出提示，请允许“专用网络”访问。设备搜索仅适用于可互相广播的同一局域网；访客 Wi-Fi 或 VLAN 隔离时，请手动填写地址。

如果助手电脑无法连接，可以在助手电脑执行：

```powershell
Test-NetConnection 192.168.1.20 -Port 8765
```

将 `192.168.1.20` 替换成电脑 A 的实际 IPv4 地址。不要使用 `127.0.0.1`，它只代表当前电脑。

常见原因：

- 两台电脑不在同一个网段
- 使用了禁止设备互访的访客 Wi-Fi 或开启了无线客户端隔离
- Windows 防火墙未允许 TCP `8765` 或 UDP `8766`
- 填写了错误的局域网 IP 或配对码

### 校园网环境下搜不到设备

校园网通常会造成下面几种隔离，广播发现因此失效：

- 有线网与无线网属于不同 VLAN / 网段，广播不会跨三层转发。
- 无线网开启“用户隔离 / AP 隔离”，同一 Wi-Fi 下的两台电脑也不能互访，此时连单播也会被丢弃。
- 交换机或准入客户端禁用了广播、限广播，或拦截了非标准端口。

处理顺序：

1. 在助手端“指定搜索范围”里直接填共享端 IP（如 `10.20.30.45`）或网段（如 `10.20.30.0/24`），会改用单播 UDP 探测，跨网段只要路由可达就能发现。
2. 仍搜不到时，在“远程设备地址”直接填 `http://共享端IP:8765` 并填写配对码。
3. 想让广播也能工作：两台电脑都插网线接同一个交换机/宿舍网口，或者用其中一台 Windows 开“移动热点”，另一台连接该热点。
4. 确认共享端电脑的 Windows 防火墙允许 UDP `8766` 入站（发现）和 TCP `8765` 入站（画面），网络类型不要是“公用网络”。

## 常见问题

### 无法连接模型服务

模型服务无法连接或返回了错误。根据错误详情检查：

- API 地址和协议是否与服务商配置一致
- 是否填写了有效的 API Key 和模型名称
- 本机是否需要配置 HTTP 代理
- 本机网络是否能访问模型服务

### 显示 `401` 或 `403`

API Key 无效、过期或没有模型权限。

### 显示 `404`

API 地址、API 协议或模型名称不匹配。请按服务商文档核对接口根地址和协议。

### 追问按钮不可用

需要先完成一次成功的截图分析。如果追问失败，检查“对话模型”页是否填写了 API 地址和模型名称，该页签的主用预设是否有效。

### 远程画面包含共享端 App

在题目电脑点击“最小化共享端”，再重新连接或等待远程画面刷新。

## 当前限制

- 远程预览使用局域网 JPEG 帧，刷新间隔约为 400～500ms。
- 当前版本适合查看题目和截图分析，不是低延迟视频会议方案。
- 局域网传输使用 HTTP 和配对码，没有 TLS 加密，只建议在可信局域网使用。
- 当前支持 Windows x64 与 macOS Intel/Apple 芯片通用包；macOS 版本暂未签名或公证。

## 从源码运行

开发环境需要 Node.js `22.12.0` 或更高版本。

```powershell
npm install
npm start
```

如果 PowerShell 禁止运行 npm 脚本，可以使用：

```powershell
npm.cmd install
npm.cmd start
```

检查代码：

```powershell
npm run check
```

构建安装包：

```powershell
npm run dist
```

在 macOS 上构建 Intel 与 Apple 芯片通用版：

```bash
npm run dist:mac
```

该命令需要在 macOS 主机上运行，会生成 DMG 和 ZIP；Windows 安装包仍使用 `npm run dist`。

构建产物会生成在 `dist` 目录。发布安装包时建议使用 GitHub Releases，不要把大文件直接提交到源码仓库。

## 隐私与使用规范

- 截图只在点击“分析 N 张截图”后发送给配置的模型服务；追问时仅在勾选附图后发送。
- 桌面 App 将 API Key 与提示词预设保存在本机配置中；网页工作台将设置保存在当前浏览器，API Key 可选仅在页面内存中使用或存于此浏览器。
- 网页工作台的模型请求由浏览器直接发往用户配置的模型服务；公网中继只在已配对的内存连接中转发采集端配置（其中包含 API Key），不把配置、分析截图或追问内容写入磁盘。
- 不要上传包含真实姓名、账号、公司机密或其他敏感信息的截图。
